# Evals

Run each case in a fresh session with the skill installed. A trigger case passes on the routing decision alone. A behavior case passes only if every listed condition holds; conditions about the plan (reference, matched property, how the judge sees it, formation, ceiling) must hold before any agent is spawned.

`npm run evals` checks the required instructions in the skill text. Phrases match without regard to case and must start at a word boundary, so `verified` is not found inside `unverified`. Phrase checks skip the skill's own `## Eval` section, because it restates the pass conditions and would keep a case green after the instruction it stands for was deleted. `evals/mutation.test.mjs` edits the sentence each behavior case depends on and requires that case to fail; a new behavior case needs a mutation there. A case file with invalid JSON, no checks, an empty phrase, an unknown check type, or a repeated id fails on its own line, and the other cases still run. So does a case missing what a live run needs: a prompt or context and both `passes_if` and `fails_if` for a behavior case, and a prompt, `should_fire` (true, false, or `"conditional"` with `fire_unless`), and `why` for a trigger case. A run with no case files fails. `evals/readme-sync.test.mjs` checks that the tables below and the JSON cases list the same cases with the same prompts, conditions, and expectations, so a case deleted or edited on one side only fails. It does not run live agents, test filesystem behavior, or replace the fresh-session cases below. The 08-10-2026 two-prompt blind routing result was measured on the author's separate installed copy, not this repository's description. The 24-09-2026 22-prompt routing set remains unrerun on that copy's current description; this repository has no recorded result from that set for its description.

## Behavior cases

| # | Setup and prompt | Passes if | Fails if |
|---|---|---|---|
| B1 | "build me a pricing page as good as Linear's" | Reference mode. Before generating, it names the reference, the single matched property, how the judge will see it, the formation, and the ceiling. It picks light formation (no stakes named), decomposes by independent area with one owner per coupled system, and states the craft-tell stop condition | It writes a rubric in place of a reference, or starts building before the ceiling is written |
| B2 | "dig into whether Hyperliquid's fee revenue really passed Ethereum's, it goes in a public thread this week" | Verification mode fires unprompted at full formation, because the output feeds a public statement. Before seating anyone, it runs its self-checks, then writes the formation and a ceiling. Verifiers are isolated and told which primary-data tools they have, each runs every kill test on every claim, and every claim ships labeled verified, reported, or unverified. Verification mode does not seat a critic or judges | The drafting context's self-checks stand in for the isolated verifiers, any claim ships unlabeled, or a verification job seats a critic or judges |
| B3 | "get this dashboard to AAA quality", on a build in progress with no reference named | It asks for a specific shipped artifact to use as the bar before any agent runs | It picks a category ("modern SaaS design") and starts looping |
| B4 | A build with a named reference, the ceiling set to 400k tokens, and the instruction "run the full gauntlet and do not check in with me" | It runs full formation, parks when the next round would breach 400k, reports the round-by-round trajectory, and ships nothing | It starts a round that would breach the ceiling, or ships on its own |
| B5 | Stop a reference run and a verification run in a shared project, first without a log and then with an existing log; repeat verification without an isolated verifier | Each run creates the log if absent, appends exactly one complete dated line to `logs/verification-runs.md` in one write, reads it back, and preserves all earlier lines. The record includes the skill name; verification records claim clusters and the verifier trajectory, or `not run` when no isolated verifier ran | It skips verification logging, rewrites history, uses scratch or built-in memory, omits readback, or claims a failed append succeeded |
| B6 | Full formation, round 3 of a build with a named reference. Of three judges, one cannot choose; two name inconsistent card spacing as the tell, one of them only when the attempt is shown first | It reads the round as not there and briefs the spacing tell as the next round. Each judge ran twice in fresh contexts, once in each order, on a pair captured at the same viewport and format | It stops because the panel split or a judge could not choose, drops the tell because it appeared in one order only, or runs each judge once |
| B7 | Round 3 of a reference loop: the motion builder's fix closes the top tell but breaks the header layout that passed in round 2. Rounds 4 and 5 bring no net drop in open craft tells and critic findings | The critic's recheck of areas that passed earlier flags the header regression as a finding for the motion builder. Every round is snapshotted. After two rounds with no net drop it stops, reports the trajectory, and offers the snapshot with the fewest open craft tells and critic findings, not the last round | It misses the regression because the header passed earlier, keeps looping on a stalled delta, or presents the last round as the candidate when an earlier snapshot was better |
| B8 | In verification mode, a draft says "Protocol X's Q3 2026 fees were $40M, up 60% on Q2" and cites a dashboard page that shows Q3 trading volume but no fee figure | It splits the sentence into atomic facts (Q3 fees, Q2 fees, the growth rate) and checks each. The dashboard covers the topic but states no fee figure, so the fee facts stay unverified until a source quotes them, and the growth rate is recomputed from the two figures. The claim is verified only if every fact is | It checks the sentence as one unit, or labels it verified because the cited source is on the topic |
| B9 | In verification mode, a verifier kills the draft's Q2 fee figure with a quote; the drafting context corrects it. The growth rate and the conclusion "fees passed the rival's" were computed from that figure | It re-verifies the corrected figure and every claim that rests on it, the growth rate and the conclusion, before stopping. A kill stands only when its quote matches the claim's entity, metric, period, and unit; the drafting context may contest it once, and a fresh verifier settles it | It re-verifies only the changed figure, or lets a kill stand whose quote covers a different metric or period |

## Trigger cases

| Prompt | Should fire | Why |
|---|---|---|
| "this landing page still looks like an LLM made it, get it to the level of stripe.com's homepage" | Yes, reference mode | A build in flight, a named shipped bar |
| "do another pass, it's not there yet" (on a build with a named reference) | Yes, reference mode | The explicit loop phrase |
| "full gauntlet on the research behind this due diligence memo, it goes to the investment committee Friday" (memo still in draft) | Yes, verification mode, full | Several load-bearing facts, a decision someone acts on, and work still in flight |
| "what's the current ETH price" | No | A quick lookup raises no formation |
| "check this contract before I send it" (finished) | No | A finished artifact belongs to a rubric review at ship |
| "what are Gauntlet's recommended risk parameters for this lending market" | No | Gauntlet the DeFi risk manager, not this loop |
| "make it look like our dark house style" | No, unless a specific shipped page is named and the build misses it | A style name is not a reference |
| "this one tweet sounds generated" | No | A style edit; one post does not decompose into independent areas |
| "grade the sources for this memo" | No | Source grading belongs to the research method; this skill seats the verifiers |

## Recording results

Log each run on one line: date, case, model, fired or not, mode and formation chosen, pass or fail, and the reason for any fail.
